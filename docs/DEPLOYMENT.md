# Deployment

Three free services, no credit card, no always-on worker.

| Layer | Service | Plan | Region |
|---|---|---|---|
| Frontend | **Vercel** | Hobby | Global edge |
| Backend | **Render** web service | Free | Singapore |
| Database | **Neon** Postgres + pgvector | Free | Singapore |

Live: [cortex-vault-web.vercel.app](https://cortex-vault-web.vercel.app) → [cortexvault-api.onrender.com](https://cortexvault-api.onrender.com)

The backend and database sit in the same region on purpose: a chat request makes several database round trips, so cross-region latency compounds.

## What this deployment does not have

- **No Redis and no worker.** `INGEST_MODE=inline` runs ingestion in a FastAPI background task. No free host offers an always-on background worker — see [ARCHITECTURE.md](ARCHITECTURE.md) for the tradeoffs this buys.
- **Object storage is opt-in.** Cloudflare R2 support exists (`app/storage/r2.py`); unless `R2_ACCOUNT_ID`/`R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY`/`R2_BUCKET_NAME` are all set, uploaded originals are discarded after text extraction, same as before.
- **No error tracking.** Failures appear only in Render's log stream.

## Backend — Render

Deployed from [`apps/server/render.yaml`](../apps/server/render.yaml) as a Blueprint.

Two things that are easy to get wrong:

1. **Blueprint Path must be `apps/server/render.yaml`.** Render defaults to `render.yaml` at the repo root, which does not exist here.
2. **`plan: free` is declared in the blueprint.** If the Render UI shows a Starter instance, the blueprint did not apply — stop rather than deploying.

### Environment variables

Non-secret values live in the blueprint. These are marked `sync: false` and must be set in the dashboard:

| Variable | Value |
|---|---|
| `DATABASE_URL` | `postgresql+asyncpg://…?ssl=require` |
| `DATABASE_URL_SYNC` | `postgresql+psycopg2://…?sslmode=require` |
| `GEMINI_API_KEY` | Embeddings |
| `GROQ_API_KEY` | Chat |
| `CORS_ORIGINS` | `["https://cortex-vault-web.vercel.app","http://localhost:3000"]` |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` | Optional — object storage for original uploads. Omit all four and the app runs exactly as before. |

`JWT_SECRET` is generated by Render (`generateValue: true`).

> **The two database URLs differ by more than the driver.** asyncpg takes `ssl=require`; psycopg2 takes `sslmode=require`. asyncpg rejects `sslmode` outright, and the resulting startup error does not obviously point at the cause.

Migrations run on boot via `entrypoint.sh` (`alembic upgrade head`), which also creates the `vector` extension on first deploy.

## Frontend — Vercel

| Setting | Value |
|---|---|
| Root Directory | `apps/web` |
| Framework | Next.js (auto-detected) |
| `NEXT_PUBLIC_API_URL` | `https://cortexvault-api.onrender.com` |

**`NEXT_PUBLIC_*` is inlined at build time, not read at runtime.** Changing it requires a redeploy, not a restart. Setting it after the build ships a bundle pointing at `localhost:8000`.

## Database — Neon

Free tier: 0.5 GB, scales to zero when idle. `pgvector` is available without setup; the initial migration runs `CREATE EXTENSION IF NOT EXISTS vector`.

Embeddings dominate storage. At 768 dimensions each chunk vector is ~3 KB, so 0.5 GB is roughly 150k chunks before other data.

## Verifying a deploy

```bash
API=https://cortexvault-api.onrender.com

curl -s $API/health                                    # {"status":"ok","env":"production"}
curl -s -o /dev/null -w "%{http_code}\n" $API/api/v1/me  # 401

# CORS must name the Vercel origin exactly
curl -s -D - -o /dev/null -X OPTIONS $API/api/v1/auth/sign-up \
  -H "Origin: https://cortex-vault-web.vercel.app" \
  -H "Access-Control-Request-Method: POST" | grep -i access-control-allow-origin
```

An `indexed / completed` ingest status is the single most informative check — it proves the database, migrations, pgvector, the HNSW index, and the embedding provider all work together.

## Cold starts

**Render free spins down after 15 minutes of inactivity.** The next request takes ~50 seconds. Neon adds ~1 second waking from zero.

Vercel does not sleep, so the UI loads instantly and then appears to hang on the first API call. That is the shape of the free tier, not a bug. Paying for Render Starter is the only real fix; keep-alive pings burn the shared 750 instance-hours and are against the spirit of the free plan.

## Failure modes seen in practice

| Symptom | Cause | Fix |
|---|---|---|
| `Blueprint file render.yaml not found` | Path defaults to repo root | Set Blueprint Path to `apps/server/render.yaml` |
| Startup error mentioning `sslmode` | `sslmode` passed to asyncpg | Use `ssl=require` for `DATABASE_URL` |
| Browser blocks every API call | `CORS_ORIGINS` missing the Vercel domain | Add it exactly, including scheme |
| Frontend calls `localhost:8000` in production | `NEXT_PUBLIC_API_URL` set after the build | Set it, then redeploy |
| `openai.OpenAIError: Missing credentials` at boot | Provider client built at import | Construct provider clients lazily |
| `CREATE INDEX … hnsw` fails | Embedding dimension > 2000 | Keep `EMBEDDING_DIM` at 768 |
| Chat returns 429 with `limit: 0` | Model has no free-tier quota | See [AI.md](AI.md) |

## Cost

$0. Every layer is a free tier, and no credit card is on file for any of them.

Watch three ceilings:

- **Neon 0.5 GB** — embeddings dominate
- **Render 750 instance-hours/month**, shared across all free services in the account
- **Gemini and Groq free-tier request caps** — per-day, not just per-minute

## History

This project previously ran on Railway (five services: web, api, worker, Postgres, Redis). That worked well and had no cold starts, but Railway Hobby is a $5/month subscription with no free tier. The move to Vercel + Render + Neon traded a fixed monthly cost for cold starts and the loss of a dedicated worker process.

`railway.json` files were removed when the migration completed. If you go back, the queue path still exists — set `INGEST_MODE=queue`, provide `REDIS_URL`, and run a second service with `SERVICE_ROLE=worker`.
